1. Project Overview

Dynamic AI Medical Guardian is an offline-first medical assistant prototype designed to provide a simple interface for managing medical information and accessing an emergency medical dossier.

The prototype uses a browser-based interface with setup, permission preferences, PIN-based access and a medical assistant dashboard.

2. Problem Statement

Important medical information, such as allergies, existing conditions and medicine details, may not always be readily accessible when needed. A simple and privacy-conscious interface could help users organise this information and make relevant details easier to find during an emergency.

3. Healthcare Use Case

The proposed system focuses on:

- Organising personal medical information.
- Providing an interface for entering medicine details.
- Offering a dedicated emergency medical dossier interface.
- Exploring a future AI assistant for general medical information.
- Investigating privacy-conscious operation with reduced dependence on cloud services.

This prototype is not a clinically validated medical device and does not replace professional medical advice.

4. Technical Stack

- Frontend: HTML5
- Styling: CSS3
- Application logic: JavaScript
- Execution environment: Web browser
- AI model: DeepSeek API planned; not integrated in the current prototype.
- Storage: Browser-based storage where implemented.

5. Current Prototype Features

- Assistant setup and naming interface.
- Permission preference screen.
- PIN-based access interface.
- Emergency medical dossier interface.
- Main medical assistant chat interface.
- Medical and medicine information entry interface.
- Responsive, Jarvis-inspired visual design.

Mail and chat integrations, medical sensor integrations and external AI connectivity are not implemented in the current prototype. SOS functionality is simulated and should not be treated as a verified emergency dispatch service.

6. Architecture

The current prototype follows a browser-based architecture:

1. User opens the HTML prototype.
2. The setup screen allows assistant naming.
3. The permission screen displays local permission preferences.
4. The PIN interface controls access to the relevant screens.
5. The medical interface provides the available information-entry and assistant UI.
6. Emergency-related screens display the prototype's emergency information interface.

A future version may add a securely implemented AI backend, but that component is not part of the current working implementation.

7. Project Outcome and Future Scope

The current outcome is a functional user-interface prototype for exploring medical information management and emergency dossier access.

Future development may include:

- DeepSeek API integration through a secure backend.
- More robust local data protection.
- Tested medicine reminder and history features.
- Native Android capabilities, where appropriate.
- Verified emergency contact workflows.
- Usability and reliability testing.

These are proposed improvements, not claims about completed functionality.
